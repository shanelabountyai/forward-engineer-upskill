# Day 6 — Document Week 1 + start the build log

Goal: make the week legible to someone else (a hiring manager, a prospect) and start the build-log habit. Documentation is a deliverable, not an afterthought.

## Tidy the repo
1. Add or improve a `README.md` for each script/folder: one line on what it does, how to run it.
2. Make sure the top-level `fde-portfolio` README links to Day 2–5 artifacts.

## Start the build log (Obsidian)
3. In your FDE vault, open `Build Log.md`.
4. Write **one paragraph**: "What I can now do that I couldn't Monday." Be concrete — API calls, reliable JSON, tool use, a CLI built with Claude Code.

## Record a demo
5. Screen-record a **60-second** run of `brief-to-plan`: paste a brief, show the structured plan. No narration needed if time's short.
6. Save the clip (and drop it in the repo or link it from the README).

## Commit
```bash
git add . && git commit -m "Day 6: Week 1 docs + build log + demo"
```

## ✅ Proof
Documented repo + Obsidian build-log note + 60-sec demo clip. Log all three in `tracker.html`.
